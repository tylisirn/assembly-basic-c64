The implemented cartridge is a development build. The revision 0.3 version-one contract remains the release target. Updating the design records actual choices and unfinished requirements; it does not waive those requirements or assert release acceptance.

## User-reported VICE validation — 10 October 2026

After the revision 0.6 Magic Desk conversion, the user successfully loaded Void Runner from disk, ran it and played the game in VICE. Garbage collection completed and gameplay continued. This supplies manual disk-load/gameplay evidence alongside the automated suite; broader emulator and physical-machine acceptance remains open. The emulator version, timing configuration and play duration were not restated for this test.

Observed collection latency remains a performance backlog item: approximately 0.25–0.5 seconds per periodic pause during Void Runner and approximately one second in the maze workload `10 PRINT CHR$(205 + (ABS(RND(1)) >> 14));:GOTO 10`. These are approximate user observations, separate from deterministic py65 cycle measurements. Firmware behavior is unchanged in this documentation update.

Future work should profile both workloads, reduce temporary-string allocation where semantics permit, and investigate reducing the worst collection pause while retaining roots, stationary native code and continuation safety. The maze allocates a fresh one-byte CHR$ string each iteration, making it a useful temporary-allocation stress case. Incremental collection would require an explicit mutation/root protocol before implementation. See [the collection investigation](VOIDRUNNER_FREEZE.md).

## Recorded architectural decisions

- Stable anchors/bindings allocate from the low end of free spans; payloads and runtime heap objects allocate from the high end, preserving common RAM for future anchor slabs. Common allocations are checked against the `$8000` boundary even for whole free blocks.
- Runtime ABI **7** reserves `$E400–$FFF9` (7,162 bytes); `$FFFA–$FFFF` holds hardware vectors. The allocator spans `[$2C00,$D000)` and `[$E000,$E400)`, totaling 43,008 raw bytes. The resident compiler reserves `$1400–$2BFF` (6,144 bytes). The runtime base keeps the design's permitted lower-base adjustment.
- The fixed-address runtime and resident compiler occupy raw images in banks 2 and 1. Cold start copies both images through common RAM; RUN and CONT refresh the runtime image without moving user code. The link output proves its RAM addresses; no runtime relocation is assumed.
- String collection is **nonmoving mark-and-sweep**, followed by free-list coalescing, rather than the proposed compacting collector. Roots include line/slab/name/binding objects, arrays, functions, direct code, descriptors, expression temporaries and live helper string pointers. It marks roots once per 2 KiB window using a 256-byte bitmap over inactive lexer scratch, and sweeps the sorted free list with monotonic cursors. It avoids descriptor pointer rewriting but can leave fragmented free space.
- Name interning compares complete normalized spellings through a linked dictionary. It preserves full identity but has linear compilation lookup rather than hash buckets. Scalar references bind stable cells at compile time.
- Language zero page is `$02–$78`; KERNAL service state uses `$90–$FF`. Common workspace is `$0800–$13FF`. A supported stock KERNAL audit remains a release requirement.
- `$0334–$03FF` (204 bytes) is firmware-owned common RAM: 116 bytes hold service entry stubs, leaving 88 bytes reserved for future code, data or workspace. Additional gateways are prospective; other uses remain open. Cold start copies the stubs after KERNAL initialization because `RAMTAS` clears page 3. Tape transport remains unsupported. See [the banked-service ABI](MAGIC_DESK_BANKS.md#banked-service-call-abi).
- Runtime ABI and source-container version are separate. Source files remain version **1**, magic `AB64SRC\0`, little-endian fields and CRC-16/CCITT-FALSE. Host validation is authoritative for the complete Appendix A structural and canonical checks currently implemented.

## Revision 0.11 banked execution services — 13 October 2026

- Runtime ABI is **7**, source/container version remains **1**. DATA/READ/RESTORE, DEF FN definition activation and device/channel/INPUT/GET helpers execute in bank-2 ROM through common-RAM entry stubs. Hot function calls, arithmetic, strings, arrays and collection remain in RAM.
- `bank_call` uses inline bank/map/target descriptors and per-call hardware-stack frames. It preserves full mapping, bank ownership, arguments/results and the caller's interrupt mask through nested ROM, RAM and KERNAL calls. Decimal mode is cleared at service boundaries. KERNAL, command-to-RAM, source-file entry and image-copy gateways share the ABI; SYS/USR retain their dedicated contracts.
- High-runtime usage drops from 7,037 to **5,922 bytes**, leaving **1,240 bytes**. Gateway code uses 578 bytes and low service stubs 116, a net reduction of **959 resident RAM code bytes**. ROM services occupy 1,282 bytes. Compiler and arena reservations retain their bounds.
- Static checks cover resident and ROM-service dependency closures. Regressions cover nested bank calls, full-port/flag/register/stack restoration, IRQ/NMI transition boundaries, blocking input, source/definition operands beneath ROM, unsupported-device/error recovery and startup installation after page-3 clearing. The py65 harness now models the KERNAL-visible IRQ entry and RAMTAS buffer clearing; genuine-ROM and physical-machine acceptance remain open.
- Hard-reset and reload/reenter source before using the new cartridge. Earlier snapshots preserve obsolete gateways and helper addresses.

## Revision 0.10 integer arithmetic — 13 October 2026

- Implements [the integer arithmetic specification](integer_arithmetic_design.md). Nonnegative constants are unsigned, negative literals are signed, and typed binary evaluation follows precedence/associativity independently of the destination. Representable naked literals adopt the local typed operand; computed constant subexpressions retain their types. Mixed arithmetic remains signed. Assignment copies the low 16 bits without range checking.
- `PRINT 20000+20000` prints 40000; assigning it to A stores -25536. `4-5` is unsigned 65535 and `(4-5)/2` is 32767. `U%=40000:B=2` gives unsigned 20000 for U%/2 and signed -12768 for U%/B; B=-2 changes the latter to 12768. PRINT/STR$, ordering and division consume the expression's type. VAL and declared function results retain their types.
- Power-of-two multiplication/division uses shifts in either signed or unsigned expressions. Signed division retains truncation toward zero; unsigned division uses zero fill, including operands above 32767. Literal $8000 means unsigned 32768; a mixed signed division reinterprets it as -32768. General constant folding remains unimplemented.
- Runtime ABI is 6; source version, two-byte cells/array elements, expression tags and RAM/arena boundaries remain unchanged. Compiler strength-reduction routines moved to command bank 0 to preserve RAM headroom. Hard-reset and reload/recompile source for changed native helper addresses and literal semantics.
- The specification's A# 16.16 fixed-point type remains planned. Integer arithmetic is the scope of this revision; fixed-point conversions and a remainder operator are not added.

Historical revision notes below describe their original behavior; this section supersedes earlier literal-typing rules.

## Revision 0.9 file argument validation — 13 October 2026

- SAVE, LOAD and VERIFY accept `filename[,device[,secondary]]` with default device 8. The secondary expression is evaluated once, checked as a byte 0..255 and ignored for the source-only .AB format. The sequential transport remains channel 2 and does not select a PRG load address or native-code format.
- The previous parser consumed filename/device only, emitted the file operation and then appended a syntax trap for the remaining `,1`. SAVE completed before the trap ran; LOAD returned to READY after publishing its new graph and skipped the trap. The parser now consumes the optional third argument and checks the complete statement boundary before emitting the file call.
- Extra/missing arguments and invalid secondary values fail before opening or overwriting a file. Colon and ELSE remain valid statement/arm boundaries. The enlarged file-argument parser resides in command bank 0 to stay within the compiler's RAM reservation. The execution runtime remains byte-identical at ABI 5; source-container version and arena boundaries are unchanged.

## Revision 0.8 canonical function calls — 12 October 2026

- Target and host tokenizers recognize TAB/SPC followed by optional spaces/tabs and an opening parenthesis, including shifted-letter keyword abbreviations. TAB/SPC tokens continue to include their opening parenthesis; no new token codes are introduced. Ordinary functions already accepted separate opening parentheses and retain their grammar.
- LIST and host text decoding emit compact function/array delimiters: TAB(11), CHR$(147), MID$(S$, 1, 2), A(1) and FN F(X). Grouping becomes `(1 + 2)`, with spaces retained around assignment, arithmetic, comparison and logical operators. No padding is emitted inside parentheses or before closing parentheses, commas or semicolons; ordinary separators remain between statements/arguments. Raw string, comment and DATA payload bytes are unchanged. Canonical signed DATA fields keep their sign attached to the magnitude.
- The previous game-over failure on Void Runner line 7050 treated TAB (11) as an implicitly dimensioned TAB array with bounds 0..10. Both pasted and disk-loaded source now use the TAB builtin and complete the mission-ended/high-score output. The gameplay regression covers quitting with Q and an exhausted-lives path through the game-over wait loop while checking native code remains unchanged.
- Runtime ABI remains 5, source/container version remains 1, and RAM reservations/arena boundaries remain unchanged. Updated example containers are encoded from source so spaced calls receive the corrected builtin tokens. Older .AB files that already contain TAB/SPC name tokens require text re-encoding or reentry of the affected lines; binary LOAD recompiles stored tokens rather than retokenizing text. Host period abbreviations remain an additional host convenience.

## Revision 0.7 unsigned words and FRE — 12 October 2026

- `%` identifies unsigned 16-bit scalars, array elements, function parameters and function results; unsuffixed numbers remain signed. Assignments/parameter passing copy the word without range/overflow checks. PRINT and STR$ render unsigned values as 0–65535. INT and ABS preserve an unsigned operand; SGN returns 0 or 1 for it. RND treats an unsigned nonzero argument as positive; RND results remain signed words.
- Binary arithmetic, bitwise operations and comparisons use unsigned interpretation only when both operands are unsigned. Mixed expressions use signed arithmetic, as requested. Literals remain signed words; `U%/2` is signed while `U%/D%` is unsigned. Relations still return signed -1/0. Unary negation/NOT preserve the numeric type and wrap. Existing arithmetic-right-shift semantics remain for both types; a mixed shift has a signed result. Power-of-two literal lowering retains these mixed signed semantics.
- FOR uses its declared variable's interpretation for the initial value and limit. STEP retains signed direction. Unsigned NEXT detects wrap/underflow to terminate loops at 65535 or zero. Arrays keep two-byte numeric elements; source/container vocabulary/version is unchanged.
- FRE() and compatible FRE(n) perform nonmoving garbage collection and free-block coalescing, returning the free physical arena byte total as unsigned. FRE(n) evaluates and ignores its numeric argument. They preserve live values, arrays, source, native bodies, reservations and continuations; they do not perform the destructive stopped CLEAN rebuild. Free-block header bytes are included, and fragmentation can limit an individual allocation.
- Expression tags are signed 0, string 1 and unsigned $80. Array descriptor type uses bit 0 for strings and bit 7 for unsigned words. Collectors inspect string tags explicitly so unsigned numeric words cannot become accidental descriptor roots. Static scalar loads select signed/unsigned push helpers during compilation. The runtime ABI is now 5; RAM reservations and the 43008-byte raw arena remain unchanged. Hard-reset and reload/recompile source for the new helper addresses.

## Revision 0.6 cartridge conversion

- Bank 0 supplies commands/editing and the common-RAM gateway load image; bank 1 supplies the resident compiler; bank 2 supplies the execution runtime. Banks 3–7 contain recovery headers and otherwise erased space reserved for future features. [The bank plan](MAGIC_DESK_BANKS.md) records placement and transition contracts.
- Bank selections update `$DE00` and the common-RAM shadow at `$0BE3`. Image copies run with IRQs masked, restore the complete port and bank, and preserve interrupt flags. KERNAL and IRQ paths preserve bank state; NMI stays in RAM. SYS/USR and command recovery establish bank 0 after restoring I/O visibility.
- The runtime ABI is 4; `.AB` source version is still 1. Native code from earlier cartridges must be regenerated after hard reset. No additional RAM arena space is claimed.
- Improved editing, stock PRG import/export, 16.8 fixed-point, custom PRINT and sprite/VIC/SID commands are planned extension roles, not current language features. Moving compiler/runtime helpers into banked ROM requires a separate call ABI and RAM-budget review.

## Revision 0.5 semantics

- Enter explicitly outputs the screen-editor carriage return before parsing/output, including blank lines. Successful numbered edits/deletions produce no READY prompt. Recoverable lexical/assembly failures report an error and retain their tokens and deferred runtime trap. Resource exhaustion retains the previous line.
- LIST accepts exact numbers and inclusive/open ranges in 0–63999; a reversed range produces an empty listing. It emits a newline before the first listed line.
- ELSE binds to the nearest unmatched IF on its physical line; colon-separated arms and literal line targets are supported. An unchosen arm does not execute. The compiler bounds pending IF depth to 32 and patch count to 64.
- RND uses a full-period word LCG, `state = (25173*state + 13849) mod 65536`. First positive use seeds from the low word of RDTIM, zero repeats, and a negative argument supplies its complete two's-complement seed before advancing. It returns every word bit; normal display is signed.
- Shift counts are checked unsigned bytes. Arithmetic right shift sign-extends; left shift wraps. Counts ≥16 saturate to zero/sign fill. Precedence from high to low is power, unary +/- , multiplication/division, addition/subtraction, shifts, comparisons, NOT, AND, OR. Existing eager evaluation and left associativity remain.
- Literal power-of-two multiplication in either operand uses the shift helper. Literal power-of-two divisors use a biased arithmetic shift that preserves signed division toward zero; the $8000 word divisor (-32768) additionally negates the quotient. General variable arithmetic retains the generic helpers.
- CLEAN is direct-only. It serializes referenced source to a temporary RAM container, builds a second graph, densely rebinds names and slabs, publishes it, clears values/continuations and collects unreachable objects. Referenced missing targets retain undefined anchors. Snapshot/rebuild allocation failures restore old source and release temporary storage. CLEAN needs temporary headroom and does not promise sliding compaction of every arena object.

- RESERVE (token $6A) is a compile-time declaration outside IF. Its unsigned literal address/count must be multiples of 256, with a nonempty range wholly inside one arena span. The allocator removes a wholly free range atomically, preserving free fragments of at least four bytes; up to eight ranges live in fixed common state, outside the writable user regions. Collection skips these regions without reading user bytes as headers. Duplicate bounds are harmless; occupied/overlapping regions fail safely. RUN, CLR, edits and CLEAN preserve reservations; NEW releases them. SAVE/LOAD retain numbered declarations. Removing source or failed import does not release reservations before NEW.
- Void Runner previously used $C200–$C217 as star data while compiled BASIC lines 400/410 occupied the same bytes, causing execution of overwritten instructions and a CPU JAM. Its first line now reserves $3C00–$3DFF and $C000–$C2FF. The stock BASIC memory-top POKEs at decimal 55/56 have been replaced; this language has separate zero-page ownership.
- Program reset/clear helpers reside in the compiler image. Revision 0.6 replaces the earlier compressed images with raw banked copies.

- The later Void Runner freeze was a very long collection pause on a valid heap. Captured-heap replay now takes 1,269,981 simulated CPU cycles for a full collection versus 137,980,792 cycles for only the old collector's remaining work. Both produce the same nine free blocks and 5,651 free bytes, preserving all live allocations and reserved game regions. See [the investigation](VOIDRUNNER_FREEZE.md) and [measurements](voidrunner-collection.json).
- Error output and command allocator wrappers share the resident compiler image. Its RAM reservation remains unchanged in revision 0.6.

## Releasing version one

Resolve the remaining behavior above, then execute the original section 14 acceptance corpus with genuine KERNAL ROMs, a cycle-accurate emulator, and PAL/NTSC machines. Include every bank-transition interrupt boundary, hardware stack maximum, allocation-failure site and source corruption boundary. Publish measured capacity, startup/copy latency and representative native speedups with normal VIC/IRQ activity. The current harness results cannot substitute for that evidence.
