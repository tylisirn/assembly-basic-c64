Binary/Sprite editor (repurpose another bank for this from the reserves).
Activate with F5 in the Basic editor or with direct command SPRDEF.

Border areas in the reference images have been coloured cyan for clarity of where the border areas end, but they should be the standard light blue.

# Reservation / Blob editor

The editor opens into the memory reservation screen where the user can create and edit reserved sections of memory and binary blobs inside them. The commands on the bottom are context sensitive. Operations on memory areas do not affect the bytes currently in memory, unless specified to.

The selection cursor starts in reservation select mode. The user can move selection up and down, and select which reservation's blobs to edit with return. DEL deletes the reservation under cursor. If the reservation is not empty, prompt for deletion. N creates a new reservation (prompt user for start address and size in bytes). S saves the bytes of the currently selected reservation onto disk as a sequential .BIN file. L loads a .BIN file and places the bytes in the selected reservation. S and L prompt the user for filename.

R allows redefining the reservation/blob start address and size. Prompt for new start address and new size.

RETurn enters the selected reservation and allows the user to select and edit individual binary blobs inside the reservation. A blob can have type SPR (sprite), BIN (binary), and ASM (assembled code). N new blob creates a new blob inside the reservation. Prompt user for blob type. If blob type is sprite, size is automatically set to 64 bytes. Otherwise prompt user to enter size. S and L saves and loads the bytes of the blob. C allows changing blob type.

RETurn switches to the appropriate editor depending on the blob type. ASM is reserved for future and open the binary editor. BIN opens the binary hex editor. SPR opens the sprite editor.

# Binary editor

Binary editor shows top status bar which lists the extent of the binary blob. Bottom status bar shows the byte currently being edited, as well as the hex and decimal representation of both the current byte alone and the 16-bit word if combined with the next byte.

The main area shows the address, the hex codes with editor width of 8 bytes per row, and PETSCII representation of the bytes. Nonprintable PETSCII characters show up as periods.

Cursor keys move the selection. I initializes the whole blob to a value (prompt user for the value). T allows changing the type of the blob (editor does not change). The user can edit the hex value under the cursor by typing in a hex value. Space, comma and return move to the next value, otherwise the cursor remains on the current value.

# Sprite editor

Sprite editor is normal character mode screen with dark blue background colour.

Sprite editor shows an enlarged edit view of the spire encoded in the blob bytes, along with 1x and 2x previews. The edit view is implement using characters, the 1x and 2x previews use hardware sprites. The editor cursor is implemented with a hardware sprites (two overlayed hires sprites to draw a black-white hatched outline around the pixel being edited).

Hires sprites map to 1 character per pixel. Multicolour sprites map to 2 characters per pixel. The cursor sprites are swapped accordingly.

Around the edit window is rulers counting rows and columns. Right side shows the preview area and hotkeys. Cursor keys move the editor cursor. 1 changes the pixel under the cursor to the sprite's defined background colour (00). 2 changes the pixel to the sprite's defined sprite colour (10). 3 changes to the common sprite color 1 (01). 4 changes to the common sprite color 2 (11).

Hires sprites only show shortcut keys for colours 1 and 2. Multicolour sprites show shortcut keys for all 4 possible colours.

C allows defining what these 2/4 colours are. Prompt the user to select which colour definition to set, then allow user to select the colour with a colour picker.

Each sprite saves its own background, sprite and common colours settings in its metadata.

I allows to initialize the sprite data to any of the 2/4 colours.

S and L saves and loads the sprite's bytes.

T changes between interpreting the sprite data as hires or multicolor sprite.

B allows setting the value of the unused 64th byte of sprite data. The legend shows the current value of the byte. When selected prompt the user to set the new value.

# Data handling

Save saves the exact bytes of the memory range belonging to the selected blob/reservation. No metadata is saved in the .BIN file.

Load loads the bytes from the .BIN file into the memory range of the selected blob/reservation. If there are less bytes in the .BIN, the rest of the memory is unchanged. If there are more bytes in the .BIN, the loading stops once the blob's/reservation's range is filled.

The purpose is to allow flexibly save/load and exchange the bytes of a blob between programs.

The metadata for the reservations and blobs is stored with the BASIC program. When a BASIC program is saved the metadata and the bytes in each blob is saved in the .AB file. Loading an .AB BASIC program the reservations and data is restored to memory.

BASIC RESERVE command creates reservations. These reservations are marked (BASIC). The size or start address of these reservations can not be changed, but blobs can be created inside as normal.
