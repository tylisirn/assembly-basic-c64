# Assembly BASIC implementation summary

## Revision 0.16 — advanced binary/sprite editor

F5 or direct SPRDEF opens the reservation/blob manager, eight-byte hex view and character-based hires/multicolor sprite editor. Hardware sprites supply 1X/2X previews and a complementary black/white hatched cursor. Bounds/type changes preserve bytes; initialization is explicit. Each sprite retains its palette and mode. BIN exchange is exact and bounded; BASIC SAVE/LOAD persists metadata and blob bytes in source v2 while retaining v1 compatibility. The host codec preserves these sections. Banks 4/5 provide the UI and storage services, with page-2 metadata outside the arena and KERNAL-owned tables. Runtime ABI 7 and the existing arena remain unchanged. See [binary editor documentation](docs/BINARY_EDITOR.md).

## Revision 0.15 — LIST break, F3 line navigation and stock PRG import

LIST responds to RUN/STOP and pending cartridge breaks. F3 opens an incremental line-number prompt; any non-digit closes it without submitting the pane. Off-screen F3 and numbered-entry jumps retain up to three preceding BASIC lines for context, with wrapped context bounded so the destination stays visible.

LOAD recognizes stock BASIC V2 PRGs at $0801 and converts them on the cartridge into the existing staged source graph. It preserves two-character stock variable identity, maps signed `%` variables to distinct signed `PRGINT` names, and retains literal strings and REM/DATA bytes. Malformed, truncated or oversized PRGs and appended machine-code payloads roll back to the prior program. The existing integer execution contract still applies; SAVE writes native `.AB` source. The importer shares bank 3 with the editor, with ABI 7 and the arena unchanged. See [PRG import rules](docs/PRG_IMPORT.md).

## Revision 0.14 — pane navigation and independent literal entry

Errors return to the start of the failed command, including after pane scrolling. Cursor keys revisit earlier visible commands and output, with wrapped rows kept together for editing and submission. Numbered entry selects the affected BASIC line and scrolls it into view; the number highlight remains visible while editing. INS switches INSERT/OVERWRITE, and CTRL+2 toggles literal entry independently in both command editing and keyboard INPUT. Help and status show both settings. The implementation uses existing editor RAM and leaves runtime ABI 7 and the user arena unchanged.

## Revision 0.13 — number cursor and incremental listing updates

The listing cursor highlights only line-number digits. A cached row map makes visible cursor moves and focus switches update just the number cells. Scrolling shifts existing character rows, accounts for wrapped BASIC lines, and renders newly exposed rows while preserving a clipped line's continuation. Listing color RAM is left in place. Source refreshes write only differing characters; unchanged commands, identical edits and changes outside the viewport leave listing text alone.

Help restores a saved character screen instead of reformatting BASIC, and uses the actual PETSCII 95 glyph (←) for its focus key. The row cache and help tail use the previously unused upper half of the expression-stack page. Runtime ABI 7, its native image and the user arena remain unchanged. Tests monitor screen/color writes and compare repeated scrolling with fresh viewports; stock-KERNAL validation also exercises navigation and the help glyph.

## Revision 0.12 — split screen cartridge editor

BASIC opens the bank-3 screen editor with a 20-row listing, mode/help status row and four-row command pane. It retains selected-line and viewport bookmarks, aligns wrapped source after line numbers, scrolls by five BASIC lines, and copies the selected source on Return. ← (PETSCII 95) switches focus and discards a draft on return to the listing. INS cycles INSERT, OVERWRITE and LITERAL, with the requested cursor styles. F1 shows help; F7/QUIT clear and close; RUN closes before execution.

Numbered submissions reuse the existing tokenizer/compiler and refresh the listing. Success clears the pane; errors retain the draft, display a status diagnostic and position the cursor at the top right. Direct PRINT, INPUT and other commands stay within the lower four rows without READY. Common-RAM CHRIN/CHROUT hooks preserve bank routing and restore KERNAL vectors on exit. Text and state occupy existing reserved RAM; the arena and ABI 7 execution runtime are unchanged. Tests include error/allocation/load recovery, HELP/INPUT, modes, source wrapping, cursor bounds, capacity, output confinement and persistent bookmarks. Optional stock-KERNAL validation and a character-ROM preview are available in `tools/check_editor_rom.py`; see [editor documentation](docs/SCREEN_EDITOR.md).

The original design document was committed first as `9480026`. The project now contains a working native-code development cartridge, a reproducible build, source-file tools, automated tests, examples and synchronized design documentation. The full version-one release contract is **not yet complete**; the outstanding requirements are listed in [docs/IMPLEMENTATION_STATUS.md](docs/IMPLEMENTATION_STATUS.md) and design Appendix B.

## Firmware

The cartridge initializes the C64 explicitly and supplies its own editor, tokenizer, two-pass compiler and runtime. The compiler generates 6502 instructions on the target machine. It retains binary source tokens next to each exact-sized native body; seven-byte stable anchors and each body's final successor JMP support ordered editing, forward branches and LIST without relocation tables.

RUN hides cartridge and KERNAL ROM with the `$35` execution map. Fixed-address helpers execute in upper RAM. Common-RAM gateways provide KERNAL calls, IRQ/NMI handling, SYS/USR return recovery and source transport. The raw runtime is copied from Magic Desk bank 2 at startup, RUN and CONT. Bank 1 supplies the resident compiler image at startup. Source and code can occupy cartridge and KERNAL shadow RAM.

Implemented language facilities include wrapping integer arithmetic, arithmetic shifts and word RND, signed formatting and comparisons, hexadecimal immediates, full identifier identity, strings, multidimensional numeric/string arrays, compiled DEF FN, IF/THEN/ELSE and ON, GOSUB, dynamic FOR/NEXT, DATA/READ/RESTORE, STOP/CONT, memory/device operations and clock access. Payloads allocate from the high end of free spans to preserve common RAM for stable anchors and bindings. A coalescing allocator and registered-root nonmoving string collector preserve stationary code and continuation PCs.

SAVE emits the design's source-only version-one container with dense referenced-name IDs and CRC. LOAD builds a second source graph, validates it and publishes it after completion; failures retain the old source. The host tools provide stricter format validation, canonical source exchange and a console executing the assembled cartridge through py65.

## Revision 0.10 — integer arithmetic specification

Implemented [the integer specification](docs/integer_arithmetic_design.md): nonnegative literals are unsigned, negative literals are signed, mixed operations are signed, and every operation wraps to 16 bits before the next operation. Assignment retains the word and never changes earlier evaluation. Consequently PRINT 20000+20000 produces 40000, assigning it to A produces -25536, 4-5 produces unsigned 65535, and (4-5)/2 produces 32767. Local literal context follows the existing mixed rule without extra runtime metadata: changing a representable nonnegative literal from unsigned to signed beside a signed operand changes neither the operation's word interpretation nor its signed result. Typed functions, arrays and computed subexpressions keep their own result types.

The compiler recognizes negative literal prefixes (including -32768 and parentheses around a literal) before emitting signed negation; unary minus on computed expressions and declared values preserves their type. Power keeps its existing precedence. Literal power-of-two multiplication remains a left shift. Division uses biased arithmetic shifts for signed values and zero-fill shifts for unsigned values. The $8000 divisor is unsigned 32768; only mixed signed division reinterprets it as -32768 and negates the quotient. These reductions match the generic typed arithmetic at word boundaries and after wrapped subexpressions; no general constant folder is introduced.

The compiler's strength-reduction routines moved to command bank 0. Runtime ABI becomes 6, while source version 1, numeric cells/array layouts, expression tags, reservations and the 43,008-byte arena remain unchanged. The new specification's A# 16.16 fixed-point extension is recorded as planned. New regression coverage includes the design's examples, destination independence, local precedence/context, unsigned/signed boundaries, function/array types, optimized versus generic arithmetic, source import and CLEAN recompilation. Historical revision notes below retain their original behavior; revision 0.10 supersedes their literal-typing rules.

## Revision 0.9 — complete SAVE/LOAD/VERIFY arguments

File statements accept `filename[,device[,secondary]]`, including the reported `SAVE "VOID2.AB",8,1`. The secondary expression is evaluated once, validated as a byte and discarded for the source-only container; the disk transport retains sequential channel 2. Missing/extra arguments are checked before any file call is emitted, preventing malformed argument lists from writing a file and only then raising a syntax error. LOAD likewise rejects malformed trailing arguments instead of masking the error by returning directly to READY.

The file-argument compiler routine moved to command bank 0 to preserve its RAM budget. Runtime ABI remains 5, its image is byte-identical, source format stays version 1 and RAM reservations remain unchanged. New tests cover secondary values/expressions, default arguments, SAVE/LOAD/VERIFY round trips, colon/ELSE boundaries and malformed/invalid arguments without file creation, overwrite or source publication. A full Void Runner source save/reload with ,8,1 was also checked against the original CRC-valid container.

## Revision 0.8 — canonical calls and game-over tokenization

Both tokenizers now recognize spaced TAB/SPC opening parentheses, including shifted abbreviations. LIST and host decoding render compact function/array/FN delimiters and grouping parentheses while keeping spaces around assignment and mathematical operators. For example, `TAB ( 11 )` becomes `TAB(11)`, `CHR$ (147)` becomes `CHR$(147)`, and `X=(1+2)*3` becomes `X = (1 + 2) * 3`. Token categories control spacing so raw strings, comments and DATA payloads retain their bytes. DATA sign/magnitude spelling is retained, and LIST no longer adds a trailing gap to every line.

Void Runner line 7050 formerly tokenized TAB (11) as an array reference outside its default bounds. Updated host-generated source containers and pasted source now execute the builtin correctly. Regression coverage extends through both Q and exhausted-lives game-over paths, including mission-ended/high-score output and the fire/space wait. Format tests compare target LIST with host decoding, round-trip source/container bytes and cover nested functions, DEF FN/array parentheses, DATA/REM payloads, abbreviations and identifier boundaries. Older .AB files with TAB/SPC encoded as names must be regenerated from text or have their affected lines reentered. The packaged Void Runner source container has been regenerated with the corrected keyword tokens. Runtime ABI stays 5 and source version stays 1; all RAM budgets are retained.

## Revision 0.7 — unsigned words and safe FRE()

Names ending in `%` now hold unsigned 16-bit words, including numeric arrays and DEF FN parameters/results. Assignments copy the complete bit pattern: unsigned 65535 becomes signed -1 on assignment to an unsuffixed variable, and the reverse restores 65535. Two unsigned operands select unsigned division/comparison and an unsigned arithmetic result; mixed operations use signed arithmetic. Literals remain signed. Arithmetic wraps without overflow diagnostics. PRINT and STR$ select signed/unsigned formatting; unary numeric functions preserve type where appropriate. Unsigned FOR loops support crossing 32767 and terminate at word wrap/underflow; STEP uses signed direction. Arithmetic-right-shift behavior remains unchanged.

FRE() now accepts an empty argument list and returns an unsigned free-physical-byte total after garbage collection and coalescing. Existing FRE(n) remains compatible, evaluating/ignoring a numeric argument. The runtime operation preserves values, arrays, native code, reservations and CONT; it does not invoke the stopped CLEAN rebuild. String-root checks distinguish the new unsigned tags from string descriptors. Numeric cells/array elements remain two bytes, source-container version stays 1 and runtime ABI becomes 5. Firmware, examples, design and packaged ABI metadata are synchronized; RAM boundaries remain unchanged.

New tests cover full-word bit transfers, unsigned arithmetic/division/comparisons and signed mixing, arrays/READ/INPUT/function typing, loop wrap boundaries, long imported names, CLEAN recompilation, FRE() typing and continuation preservation, and numeric values aliasing unreachable string addresses.

## Revision 0.6 — 64 KiB Magic Desk

The cartridge now uses classic Magic Desk CRT type 19 with eight 8 KiB banks at `$8000–$9FFF`. Bank 0 contains commands, editing, tokenization, LIST, source transport and the common-RAM gateway load image. Bank 1 contains the raw resident compiler and bank 2 the raw execution runtime. Banks 3–7 have recovery headers and erased space reserved for the improved editor/PRG converter, 16.8 fixed-point/PRINT extensions, VIC/SID/sprite commands, resources and expansion. The [bank architecture](docs/MAGIC_DESK_BANKS.md) defines the layout and future integration requirements.

The linker assigns fixed RAM run addresses and banked ROM load addresses in one build. Startup copies the compiler and runtime through a common-RAM banking routine; RUN and CONT refresh the runtime. The compressed-image/decompression build path is replaced with direct bank copies. Bank changes occur in common RAM, preserve the bank shadow, full port and interrupt flags during copies, and preserve bank state across KERNAL/IRQ service frames. NMI remains in RAM. SYS/USR recover bank 0 even when user code changes the I/O map; every bank supplies cold/warm recovery vectors.

The current language features remain intact, including the Void Runner fixes. Future editor, PRG, numeric, PRINT and hardware commands are not implemented by this conversion. Runtime ABI changes to 4 because gateway addresses/load architecture changed; `.AB` containers remain source version 1. The compiler still reserves 6 KiB of RAM and the raw user arena remains 42 KiB. Hard-reset and reload/reenter source after attaching this cartridge; previous snapshots contain the old runtime and native references. `tools/package.py` publishes artifacts only when build, tests and synchronized design identify the same ROM.

## Revision 0.5

The editor outputs the carriage return received from CHRIN through CHROUT before processing each submitted command, numbered line, deletion or blank line, so subsequent output and input start on the next screen line. Numbered entry and deletion resume input without READY. Recoverable lexical/compilation failures report a diagnostic immediately and retain the new source and a deferred error stub, including malformed DATA fields. LIST begins on a new line and accepts exact numbers, inclusive ranges and open endpoints.

ELSE binds to the nearest unmatched IF on the same physical line; arms can contain colon-separated statements or literal line targets. RND returns a full 16-bit word from a full-period LCG. Its first positive call seeds from the KERNAL clock; positive calls advance, zero repeats, and negative arguments reseed reproducibly.

The compiler supports arithmetic `<<` and `>>`, with shifts below addition and above comparisons. Counts are checked bytes, and counts ≥16 produce zero/sign fill. Literal power-of-two multiplication in either operand becomes a left shift. Power-of-two literal division becomes a biased arithmetic right shift, preserving signed truncation toward zero; redundant parentheses and unary plus on literals are accepted. The `$8000` divisor is signed -32768 and additionally negates the shifted quotient.

Direct CLEAN rebuilds dense anchor slabs and a dense referenced-name dictionary from a temporary source snapshot, remaps token IDs and recompiles all branches, cells, array/function records and native references. It keeps referenced missing targets, discards historical unreferenced slots/names, clears values and invalidates CONT. Allocation failures during snapshot or staged compilation retain the old source and release temporary allocations. This requires temporary headroom; it is not general sliding compaction of every allocation.

For the earlier standard 16 KiB cartridge, the compiler was linked for a 6 KiB resident reservation at `$1400–$2BFF` and stored compressed alongside the runtime. Revision 0.5 decompressed both fixed-address images. Its raw user arena was 42 KiB and runtime ABI was 3; source containers remain version 1 with additive shift/ELSE/CLEAN token codes.

## Void Runner runtime correction

The reported VICE JAM after gameplay initialization came from a memory ownership conflict. Compiled BASIC lines 400/410 occupied $C200 while Void Runner wrote its star-field coordinates there. A trace of the original pasted source reached overwritten code and a JAM opcode at $C210, consistent with the user's $C207 report and different edit/allocation histories. Sprite writes at $3C00 also needed explicit protection from future allocations.

The new `RESERVE address,bytes` declaration (token $6A) removes whole pages from a free arena span before compilation allocates source/code. Arguments are unsigned literals aligned to 256 bytes; the nonempty range must fit one arena span. Eight regions can be recorded outside user RAM. Free-list splitting preserves valid headers, and collection skips reserved pages without interpreting graphics/native bytes as allocation metadata. Exact repeats are harmless; live/overlapping allocations are rejected. Declarations act during compilation outside IF, including LOAD and CLEAN. They persist through RUN, CLR and edits; NEW releases them. Removing a declaration or a failed import may leave a reservation until NEW. POKE/SYS remain caller-managed memory operations.

Void Runner's first line now reserves $3C00–$3DFF for sprites and $C000–$C2FF for native code/workspace. Its stock BASIC POKE 55/56 memory-top idiom was removed because those locations belong to this language's zero-page state. Existing copies must be cleared with NEW and reentered with the updated first line before compilation. The source loader also now accepts zero-length STRING/DATA_TEXT payloads instead of mistakenly checking the token code as their length.

In revision 0.5, the LZSS packer minimized encoded size including eight-item flag overhead without changing its format. Program reset/clear helpers moved into the compressed compiler image, with a larger prefix occupying the first cartridge bank. Those changes fit the reservations into the former 16 KiB cartridge and fixed RAM budgets.

## Void Runner collection pause correction

The later VICE 2.4 snapshots show valid, progressing garbage collection during the score-string update on line 1930. Repeated whole-free-list and root scans for each of 1,636 physical blocks made the machine appear frozen, with the SID retaining its last waveform. This differs from the earlier memory-overwrite JAM.

The collector now sweeps free blocks with monotonic cursors and marks roots once per 2 KiB window using a 256-byte bitmap over inactive lexer scratch. It retains stationary payloads, full 16-bit sizes and reserved regions. On the captured heap, complete revised collection takes 394,049 instructions / 1,269,981 simulated CPU cycles, compared with 44,268,554 instructions / 137,980,792 cycles just to finish the old collection from the first halt. The final free list and all live allocations match exactly. Collection still causes a finite pause; these are instruction-level measurements without VIC/IRQ timing. [The investigation report](docs/VOIDRUNNER_FREEZE.md) records evidence, tests and retest instructions.

Allocator wrappers and error output moved into the resident compiler reservation. The earlier 16 KiB build split compressed images across its ROM windows; revision 0.6 replaces that arrangement with raw bank images while retaining the collector improvements.

## Measured build and verification

The exact linked section sizes, ROM checksum and memory boundaries are recorded in [dist/size-report.json](dist/size-report.json). The 65,536-byte cartridge uses runtime ABI 6 at `$E400`, with a 7,162-byte runtime reservation, a 6,144-byte compiler reservation, 3,072-byte common workspace and 43,008-byte raw user arena. The runtime occupies 7,037 bytes, compiler 5,848 bytes and gateway 538 bytes. ROM contents use 20,477 bytes, leaving 45,059 bytes distributed among eight banks. Compiler RAM headroom is 296 bytes; using spare ROM for future executable helpers requires a deliberate bank-call/RAM-layout design.

## Design synchronization and limits

The design is revision 0.10. Its Magic Desk bank plan, memory map, fixed runtime addresses, raw load images, actual interning and collection strategies, workspace and measured budgets match the implementation. Appendix B explicitly identifies incomplete release requirements. The original version-one goals remain visible instead of being silently removed.

The important unfinished areas are general arena compaction; full INPUT/GET behavior; software-stack function activations; every target-side DATA_SPELLING validation rule; canonical target VERIFY for differently numbered dictionaries; graph/interrupt/failure hardening; and cycle-accurate, genuine-ROM, PAL/NTSC and real-device acceptance tests. The checked-in cartridge should be treated as a development artifact until these are completed.

The new CRT was checked against VICE 3.7.1 `cartconv -t md`: all header and packet bytes match except the cartridge name, and conversion back to binary reproduces the ROM exactly. The user subsequently confirmed successful disk loading and gameplay of Void Runner in VICE. Collection works but pauses for approximately 0.25–0.5 seconds during the game and approximately one second during the one-line CHR$/RND maze workload. These approximate user observations are recorded as a future performance improvement in the status/design and collection report. Broader genuine-ROM, cycle-accurate and physical-machine acceptance remains open. Load the `.crt` through VICE's CRT attachment; a raw `.bin` now requires Magic Desk attachment rather than generic 16KB.
